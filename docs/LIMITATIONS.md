# exam-uncheat 탐지 한계 — 가장 먼저 읽을 문서

이 도구는 **단서**를 줄 뿐입니다. 아래는 v0.1에서 알려진 한계입니다.

## 검증 상태
- v0.1은 **시뮬레이터와 리플레이로만** 검증했습니다. 실제 하드웨어 수신률, 실제 시험장 오탐·미탐률은 측정 전입니다.
- ESP32 펌웨어는 ESP32-S3·C6 대상으로 빌드만 확인했고, **실기기 동작 검증 전**입니다. ESP32-C5 빌드는 아직 확인하지 못했습니다.

## 볼 수 없는 것
- **페어링·연결된 기기**: BLE 기기는 연결되면 광고를 멈추는 경우가 많습니다. 페어링된 스마트안경·이어버드는 BLE 광고 기반 단서로 보이지 않을 수 있습니다.
  - 운영 대책: 수거한 휴대전화를 **교실 밖**에 보관하면 안경·이어버드가 다시 연결을 찾으며 신호를 낼 수 있습니다(현장 검증 필요).
- 전원이 꺼진 기기, LTE/5G만 쓰는 기기, 유선·자기유도(루프) 장치, 전용 주파수 장치(SDR 실험 범위 밖)
- 장비별 한계: ESP32-S3/C6는 5 GHz·클래식 블루투스 불가, 채널 호핑 중 다른 채널 신호 누락 ([HARDWARE.md](HARDWARE.md))

## 틀릴 수 있는 것
- **오탐**: 같은 회사의 다른 기기(예: Meta 회사 ID를 쓰는 VR 기기), 프린터·TV의 Wi-Fi Direct, 수거된 휴대전화·에어팟이 교실 안에 있을 때
- **위조**: 시그니처는 누구나 흉내 낼 수 있습니다 (`spoofable: true`)
- **위치**: RSSI는 사람·책상·벽에 크게 흔들립니다. 좌석이나 사람을 특정할 수 없습니다. 복도·옆 교실 신호가 섞입니다
- **기준선 오염**: 빈 교실 측정 때 없던 교실 장비(프로젝터 등)가 시험 중 켜지면 단서가 됩니다

## 그래서
- 단서만으로 수험생을 지목하지 마세요. **육안 확인 절차**(안경 다리·LED·귀 확인, 안경 책상 위 검사 요청 등)를 따르세요.
- 보고서 첫머리의 고지("판정하지 않습니다")를 지우지 마세요.
